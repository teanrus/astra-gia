# 🎓 Автоматизация установки ПО для ГИА на Astra Linux SE 1.8

>Интерактивный bash-скрипт для быстрого и автоматизированного развертывания программного обеспечения, необходимого для проведения Государственной Итоговой Аттестации (ЕГЭ, ОГЭ по информатике и другим предметам) в операционной системе **Astra Linux Special Edition 1.8**.

Скрипт позволяет гибко выбрать необходимый набор программ из интерактивного меню, избегая установки лишнего софта на рабочие места экзаменуемых.

## 📦 Поддерживаемое программное обеспечение

Скрипт разделен на логические блоки. Вы можете установить всё сразу, выбрать только нужную категорию или запустить сценарий в автоматическом CLI-режиме без интерактивных вопросов.

### 🧭 Новые CLI-режимы

Скрипт поддерживает несколько режимов запуска:

- **Интерактивный режим** — стандартный запуск без параметров.
- **Категории** — `--office`, `--internet`, `--programming`, `--graphics`, `--edu`, `--all`.
- **Ускоренные режимы** — `--full-os`, `--browsers-only`, `--education-only`.
- **Проверка перед установкой** — `--dry-run`.
- **Полное обновление ОС по явному запросу** — `--upgrade-os`.
- **Список доступных пакетов** — `--list`.
- **Логирование** — в интерактивном режиме скрипт спрашивает, сохранить ли лог; для CLI-режима используйте `--save-log`. Файл `auto-install-<дата-время>.log` сохраняется в текущем каталоге.
- **Выбор ветки репозитория** — `--repo frozen|stable`.
- Категория `--edu` включает пакеты, перечисленные в разделе `[edu]` вывода `--list`, и устанавливает R7 Office из официального репозитория.

#### Порядок подготовки системы:

1. выбор ветки репозитория (Frozen/Stable)
2. проверка `/etc/apt/sources.list` и активных файлов `sources.list.d/*.list` на дублирующиеся записи (точные повторы удаляются, нормализуя пробелы и завершающий слеш URL)
3. Выполняется `apt-get update`, чтобы обновить только индексы пакетов.
4. Полное обновление ОС (`apt-get dist-upgrade -y`) выполняется только с флагом `--upgrade-os`. Без него скрипт не запускает `dist-upgrade`, `autoremove`, `autoclean` или `apt-get clean`; кэш загруженных пакетов сохраняется.
5. Установка SANE (`sane` и `sane-utils`) предлагается только в интерактивном режиме и только после подтверждения. В CLI-режиме SANE не устанавливается автоматически.

После подготовки системы формируется список выбранного ПО.

- Все скачиваемые скриптом `.deb`-пакеты доступны в [релизе v2.0](https://github.com/teanrus/astra-gia/releases/tag/v2.0);
- Базовый URL для бинарных файлов релиза задается один раз в `GITHUB_RELEASE_BASE_URL` в начале скрипта.
- при скачивании `.deb` скрипт проверяет контрольную сумму SHA-256.
- R7 Office и MAX устанавливаются только из официальных репозиториев.
- Яндекс Браузер, IDLE, Basic 256, Scribus и Audacity устанавливаются через `apt install` из репозитория Astra.

## 🚀 Установка и запуск

### 1. Скачивание скрипта

```bash
# Создать каталог для скриптов
mkdir -p ~/inst

# Перейти в каталог
cd ~/inst

# Cкачать скрипт
wget https://raw.githubusercontent.com/teanrus/astra-gia/main/scripts/auto-install.sh -O auto-install.sh
```

### 2. Запуск

#### Интерактивный режим (по умолчанию)

>Скрипт запросит пароль `sudo` при выполнении системных операций.

```bash
sudo bash auto-install.sh
```

#### CLI-режим

```bash
bash auto-install.sh --repo stable --office --internet
bash auto-install.sh --full-os
bash auto-install.sh --upgrade-os
bash auto-install.sh --browsers-only --dry-run
bash auto-install.sh --education-only --list
```

При запуске через `sudo` весь скрипт, включая скачивание файлов, работает с правами `root`. Используйте этот вариант только если это разрешено настройками системы и локальными правилами безопасности.

> **Мандатный контроль Astra Linux:** `sudo` предоставляет административные права, но не отключает мандатное управление доступом. Если система запрещает чтение или запуск файла из-за его метки/уровня целостности, запуск через `sudo bash` сам по себе это ограничение не устранит. Запускайте скрипт из разрешенного администратором каталога; не отключайте мандатный контроль ради установки.

### 3. Работа с меню и CLI

- Запуск без параметров — обычный интерактивный режим.
- `--dry-run` — показывает список пакетов, которые будут обработаны, без реальной установки.
- `--list` — выводит доступные категории и программные пакеты.
- Перед настройкой репозиториев скрипт определяет версию из `/etc/astra_version` или `/etc/os-release` и проверяет, что это Astra Linux 1.8.
- В интерактивном меню доступны Stable для 1.8 и, если версия поддерживается, Frozen именно для установленного выпуска (1.8.4, 1.8.5 или 1.8.6). В CLI-режиме без `--repo` автоматически выбирается соответствующий Frozen; если для установленной версии Frozen не поддерживается — Stable.
- `--repo frozen|stable` — явно выбирает ветку; `--repo frozen` доступен только для версий, для которых скрипт знает адрес Frozen-репозитория.
- `--full-os`, `--browsers-only`, `--education-only` — быстрые presets для типовых наборов.
- Обычная установка обновляет индексы пакетов и устанавливает выбранное ПО, но не обновляет всю ОС. `--upgrade-os` отдельно запускает полное обновление через `apt-get dist-upgrade`; эта операция может скачать и обновить множество системных пакетов, включая ядро. Удаление пакетов и очистка apt-кэша автоматически не выполняются.
- В интерактивном режиме можно подтвердить установку R7 Office и MAX из официальных репозиториев; параметры `--r7-office` и `--max` включают эти установки в CLI-режиме.

Для работы через SSH установка предварительно задает русскую раскладку `keyboard-configuration` через debconf и запускает пакетные операции с noninteractive frontend, поэтому настройка не требует локального синего диалогового окна.
- Выберите нужную версию Python из списка.
- Дождитесь завершения скачивания, установки и очистки временных файлов.

## 🛠 Как это работает (под капотом)

- Выбор режима: Скрипт может работать как интерактивный мастер или как CLI-процесс с флагами.
- Активизация репозиториев: В зависимости от ветки (`frozen` или `stable`) добавляются нужные deb-репозитории для Astra Linux 1.8.
- Подготовка системы: Скрипт отключает CD-ROM репозитории, настраивает apt и обновляет индексы пакетов. Полное обновление ОС выполняется только с `--upgrade-os`; очистка apt-кэша и автоматическое удаление пакетов не выполняются.
- Сборка очереди: На основе выбранной категории или интерактивных ответов формируются массивы URL-адресов и имен пакетов.
- Скачивание .deb: Создается отдельная директория `tmp_deb.*`, куда через wget скачиваются выбранные пакеты.
- Установка: Выполняется `sudo apt-get -f -y install` для скачанных файлов (используется apt-get вместо dpkg для автоматического разрешения зависимостей).
- Установки пакетов запускаются с `DEBIAN_FRONTEND=noninteractive`: debconf-диалоги не открывают полноэкранное синее окно и используют ответы по умолчанию, что позволяет установке завершаться по SSH.
- Прогресс загрузки `.deb`: `wget` использует однострочную progress bar; обновления прогресса записываются в лог в той же строке для каждого пакета.
- Настройка репозиториев: Если выбрано, скрипт автоматически добавляет GPG-ключи и sources.list.d для R7 Office и MAX.
- Очистка: В конце интерактивного запуска скрипт спрашивает, оставить ли скачанные `.deb` для дальнейшего использования; при ответе «нет» они удаляются. В неинтерактивном режиме пакеты удаляются автоматически. CD-ROM репозитории восстанавливаются до этого вопроса.
  
>⚠️ Важные примечания
>Сетевые ограничения: Если на компьютерах в экзаменационном пункте стоит строгий фаервол/прокси, убедитесь, что разрешены подключения к easyastra.ru, github.com, downloads.r7-office.ru и download.max.ru.
>Версии Python: Пакеты Python 3.9–3.14 из релиза v2.0 собраны для ALSE 1.8 и проверяются по SHA-256 до установки.
>Повторный запуск: Скрипт можно запускать многократно. Если пакет уже установлен, apt просто пропустит его или обновит, если доступна новая версия.

Для `.deb`-файлов, скачиваемых из GitHub Releases, скрипт загружает отдельный sidecar-файл `<имя-пакета>.deb.sha256` из того же релиза и проверяет SHA-256 до установки. Если файл контрольной суммы отсутствует или сумма не совпала, скрипт прекращает установку. Workflow `.github/workflows/release-checksums.yml` создаёт отдельный `.sha256` для каждого вложения релиза (включая пакеты и архивы) и общий `SHA256SUMS`; он запускается при публикации релиза. Для существующего релиза v2.0 запустите workflow вручную через GitHub Actions с тегом `v2.0`.
