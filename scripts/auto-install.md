# Скрипт `auto-install.sh` Общее описание, требования и принцип работы

>`auto-install.sh` — Bash-скрипт для подготовки репозиториев и установки выбранного программного обеспечения на Astra Linux Special Edition 1.8 (x86_64). Скрипт поддерживает два способа выбора приложений:

- интерактивный мастер с вопросом по каждому приложению;
- автоматические наборы и действия через параметры командной строки.

## Требования

- Astra Linux Special Edition 1.8, архитектура x86_64.
- Пользователь с правами `sudo`. Запускайте скрипт от обычного пользователя, чтобы системные команды выполнялись через `sudo`.
- Доступ к сети для загрузки пакетов и обновления индексов APT.
- `bash`, `apt-get`, `sudo`, `wget`, `curl`, `sha256sum`; для установки и проверки пакетов также требуются системные инструменты Debian/Astra (`dpkg`, `dpkg-deb`). Для репозитория MAX используются `gpg` и `apt-cache`.

## Получение и запуск

```bash
mkdir -p ~/inst
cd ~/inst
wget https://raw.githubusercontent.com/teanrus/astra-gia/main/scripts/auto-install.sh -O auto-install.sh
bash auto-install.sh
```

Не запускайте весь скрипт через `sudo`, если в этом нет необходимости: он использует `sudo` для системных действий, а загруженные `.deb` сохраняет в каталоге текущего пользователя. Если скрипт всё же запускается от root через `sudo`, он старается восстановить владельца каталога загрузок.

> **Мандатный контроль Astra Linux:** наличие прав `sudo` не отключает мандатное управление доступом. Запускайте файл из каталога, доступного согласно политике безопасности системы; не отключайте мандатный контроль ради установки.

## Общее поведение

1. Кроме режима `--list`/`--help`, скрипт определяет версию ОС по `/etc/astra_version` или `/etc/os-release` и отказывается работать с версиями вне ветки Astra Linux 1.8.
2. Выбирается ветка репозитория Astra: Stable или Frozen для установленного выпуска. Подробнее — в [описании CLI](./auto-install-cli.md) и [руководстве по интерактивному режиму](./auto-install-interactive.md).
3. Скрипт настраивает источники Astra, отключает CD-ROM-записи на время операций, исправляет известные старые записи R7, удаляет точные дубликаты APT-источников и выполняет `apt-get update`.
4. Полное обновление ОС не выполняется по умолчанию. Для этого укажите `--upgrade-os`: скрипт запустит рекомендованную Astra утилиту `sudo astra-update -A -r -T` после обновления индексов и до установки выбранных приложений. Подробности — в [описании CLI](./auto-install-cli.md).
5. Пакеты из GitHub Releases загружаются в `deb-downloads` в текущем каталоге и остаются там после завершения. Для релизных `.deb` проверяются SHA-256 и формат Debian-пакета. Старые файлы из `tmp_deb.*` могут быть использованы повторно только после проверки контрольной суммы.
6. Установка скачанных `.deb` выполняется через `apt-get -f -y install`, чтобы разрешить зависимости. При неудачной групповой установке скрипт повторяет установку `.deb` по одному. Установленные версии новее скачанных не понижаются.
7. Пакеты Astra устанавливаются через `apt-get install`; R7 Office и MAX используют собственные репозитории. Для R7 Office используется кодовое имя `astralinux` согласно [инструкции R7 Office для Astra Linux](https://support.r7-office.ru/desktop-editors/install/linux_install_de/install_r7_de_astralinux/). Если настройка или установка из официального репозитория R7 Office не удалась, интерактивный запуск предлагает установить `r7-office.deb` из GitHub Releases; файл и его `.sha256` должны быть опубликованы в текущем релизе. Для неинтерактивного запуска резервный пакет можно выбрать заранее флагом `--r7-office-release`.
8. Перед завершением восстанавливаются CD-ROM-записи. Если загрузка или установка `.deb` завершилась ошибкой, скрипт выводит список таких пакетов и возвращает код завершения `1`. Ошибки настройки репозитория или обновления списков APT выводятся явно; если резервный пакет R7 не выбран или не установлен, скрипт также завершается с кодом `1`.

Скрипт не запускает `autoremove`, `autoclean` или `apt-get clean`.

> **Примечание о загрузке:** для загрузки `.deb` используется `wget --no-check-certificate`. Релизные пакеты дополнительно проверяются по SHA-256, но используйте скрипт только в доверенной сети и с проверенными источниками.
